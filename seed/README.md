# Bootstrap language implementation

`languages/schema.schema` describes the schema surface; `schema.coil` consumes its generated parser and performs the remaining semantic checks:

```
(node Add (left Expr) (right Expr))
(node Expr (value Int))
```

Names are symbols. `Int`, `Bool`, and `Text` are scalar types; other field types name nodes, including forward or recursive references. Node names cannot reuse scalar names. Node and field declarations must be unique in their respective scopes. Empty schemas and nodes without fields are valid. `emit.coil` derives distinct reference types, row layouts, append constructors and checked lookups.

`parse(allocator, source-text, source-id)` produces a checked schema or a diagnostic with a byte span and source identity. The caller supplies an arena and retains both that arena and the source text for the schema's lifetime. Failed parses, generated parse tables, interned names and the semantic adapter use the same arena lifetime. The seed uses the standalone `coil.reader` library for s-expression syntax; it imports no compiler frontend modules. This reader dependency belongs in bootstrap size and dependency accounting.

Run `coil run tests/schema.coil`, also under `--debug-checks` and `--release`. The suite covers forward references, declaration/field errors, malformed syntax and exact source spans. The hardcoded byte offsets refer to an inline string, not line numbers in a source file.

Build and validate generated code with `python3 tools/check-seed.py`. The seed reads a schema from stdin and writes a `rewrite.generated` Coil module to stdout by default; an optional `(module qualified.name)` declaration selects another module. Diagnostics go to stderr. Output module names use portable ASCII identifier segments separated by dots; duplicate declarations and malformed names are rejected. Numbered names are internal and avoid collisions with source symbols and Coil keywords. Node references become distinct `N0Id`, `N1Id`, etc.; rows hold scalar values and typed IDs, and growable tables store rows. Numeric assignments depend on schema order and cannot be persisted without schema identity.

IDs survive table growth and checked lookups reject negative and out-of-range indexes. IDs are local to a table: the current API does not distinguish two tables of the same node type, prevent forged IDs, or check the references inside an appended row. Raw table append APIs accept borrowed Text; generated Store readers and transformations intern owned copies. Graph validation and store-qualified IDs remain required before this is a complete compiler IR. Recursive layouts compile without recursive by-value storage.

The generator uses Coil and StrBuf emission to derive layouts and operations from checked schema fields, with no embedded user code. The schema shape parser is now generated by these same facilities; semantic adapters and the other language compilers remain Coil. Complete compiler replacement and language-toolchain self-description remain unfinished.

Sum declarations now describe variants of a single node identity:

```
(sum Expr
  (Literal (value Int))
  (Add (left Expr) (right Expr))
  (Choose (condition Bool) (yes Expr) (no Expr)))
```

A sum emits one nominal ID type and one Coil sum row, with constructors `N0V0`, `N0V1`, etc. Variant names are unique within the sum; field names are unique within a variant. Sums require at least one variant. References resolve against node/sum names, not constructor names. Thus both Add operands reference any Expr variant, and representation size stays finite. Tests build a recursive expression graph, grow its table, evaluate it through exhaustive generated-variant matches, and check malformed declarations. The evaluator in the test is handwritten acceptance code; judgment compilation has not been implemented.

The first judgment surface is now compiled:

```
(judgment Expr
  (Integer Int)
  (Boolean Bool)
  (Add Int (left Int) (right Int)))
```

A judgment names a declared sum, gives exactly one case per variant, and checks zero or more child premises before returning a scalar type. Premises must name fields referencing that same sum. The seed checks coverage, duplicate judgments, field existence and premise/result types before publishing output. It generates direct variant dispatch and recursive native calls; no rule interpreter runs in the generated checker.

The generated `judge-N` API returns a `Judgment` sum: `Typed` carries 1/2/3 for Int/Bool/Text, `Mismatch` identifies the child ID, field, expected/actual types and premise byte span, and `InvalidReference` and `CyclicInput` distinguish graph errors. Nested failures propagate unchanged; premises run in declaration order and the first failure wins. Recursion has a table-length depth budget, sufficient for any acyclic path through that table, rather than an arbitrary constant cutoff. Very deep valid graphs can still exhaust the native stack; iterative scheduling and memoization are future work. The result retains the failing premise but not a full ancestry trace or original expression source span. This finite kernel is not Coil's type system: contexts, type variables, unification, elaboration, bidirectional checking and richer result schemas remain to implement.

Schema parsing currently recognizes and defers judgment forms to the judgment compiler. The command publishes no generated source if judgment validation fails. The command reads the source once and shares those parsed forms between schema validation and judgment compilation.

Rule-local inference variables use a `?` prefix:

```
(Choose ?result (condition Bool) (yes ?result) (no ?result))
```

The first premise naming a variable binds it to that child's synthesized type. Later premises using the variable require equality with the binding; the rule result may return it. Distinct variables bind independently. Variables are scoped to one variant rule, and a result variable without a premise binding is rejected at its source span. Rule compilation assigns local slots by first occurrence, so variable spelling does not enter generated identifiers. Premises still execute in source order and preserve first-failure behavior.

This implements local inference over concrete scalar types, not general unification of type constructors or polymorphic type schemes. The conditional fixture exercises both Int and Bool results, disagreeing branches, and an invalid condition. A separate projection rule exercises independent variables. Contexts for variables/lets/functions and bidirectional checking remain required for the frontend slice.

Lexical topology is declared once and consumed by checking and lowering:

```
(bindings Expr
  (Variable (reference name))
  (Let (scope body name)))
; Judgment cases:
(Variable (lookup))
(Let ?body
  (value ?value)
  (body ?body (with ?value)))
```

`lookup` uses the reference field selected by the binding declaration and returns the nearest binding's type, or `UnboundName` with the expression ID and name. `with` supplies one type payload per declared name, in declaration order. Each type must be a scalar or a variable bound by an earlier premise; it cannot depend on the premise whose context it extends. Each extension exists only for that recursive premise. The judgment must check every declared scoped child exactly once, with the declared payload count. The implementation uses immutable linked stack frames, so returning from a child restores the parent's context without mutation or cleanup bookkeeping. The empty root context is a sentinel and is never followed to its null parent.

This lets the rules specify non-recursive let scope: value in the outer context, body in the extended context. Tests check unresolved names, shadowing, outer-name use in an initializer, and sibling isolation. Binding Text is borrowed from the expression table; the table and its strings must outlive a judgment call. General namespace resolution, mutually recursive bindings and environment-dependent caching remain unimplemented.

Schemas also derive constructor readers and a multi-table `Store`. `parse-N(store, form)` reads a `coil.reader/Sexp` into the corresponding node table. For example:

```
(Let "x" (Integer 42) (Add (Variable "x") (Integer 1)))
```

The schema controls constructor names, arity, scalar validation and recursive dispatch, including references between different node types. The reader emits children before parents and returns a nominal ID. `store-new` initializes the tables, `store-free!` releases them. A parallel origins table keeps compact source ID/start/end spans for every row created by the reader, without retaining reader trees. Text fields are interned into the Store. Register source documents with `store-source!(store, id, name, text)` to retain owned source text for diagnostics and transformations; reader storage can then be released independently. Manually appending directly to row tables bypasses origin tracking and must not be mixed with reader-owned store construction.

On a failed parse, previously appended child rows remain in the store; discard that store/arena if transactional behavior is required. No partially constructed parent is published. The generated reader currently recognizes explicit constructor syntax, not Coil surface syntax. Tests run source through the generated reader and judgment checker, exercising lets, shadowing, invalid names, branch disagreement, malformed fields/arity and unknown constructors in debug, debug-checks and release. The standalone reader and generated table machinery are still bootstrap dependencies to count.

`types.coil` introduces the concrete type store needed for function judgments. Scalar IDs remain Int=1, Bool=2, Text=3. `function(store, argument, result)` interns a unary function type and returns its canonical ID; argument and result can themselves be functions. `as-function` safely decomposes one. The pair index uses two checked 32-bit IDs packed into a u64, so pair equality is exact and lookup does not scan the type table. Exhaustion returns `TypeCapacity`; invalid component IDs return `InvalidType` before any mutation.

IDs belong to one type store and are meaningful only while it lives. Callers must not mutate the store's backing tables directly or compare IDs from different stores. This API currently handles concrete unary function types, not unknown metavariables, recursive types, polymorphic schemes, multi-argument signatures, or effects. Generated judgment calls now take a caller-owned type store as their first argument, so returned function IDs remain valid until that store is released. The implementation is handwritten Coil runtime machinery pending self-description, and counts toward the total authored size.

`tests/types.coil` checks canonical reuse, argument/result distinction, higher-order signatures, invalid IDs and 10,000 nested signatures across growth; `tools/check-seed.py` runs it in all three build configurations.

Judgment result terms can construct function types:

```
(LambdaInt (Fn Int ?body) (body ?body (with Int)))
```

The LambdaInt schema declares `(LambdaInt (scope body name))` in its binding rules. `Fn` terms nest recursively, and their leaves are scalars or previously inferred rule variables. The seed validates every nested term and rejects unbound variables before generation. Generated code interns the resulting type in the caller's `rewrite.types/Types` store; construction errors propagate as `TypeConstruction`. The generated module imports that runtime, which must accompany generated output. The acceptance harness copies the exact source into its isolated consumer projects.

The public signature is now `judge-N(type-store, rows, id)`. Context bindings and type-variable equality operate on canonical IDs from that same store. Tests parse and check identity functions, let-bound functions and nested function results, then decompose the returned types before releasing the store. LambdaInt/LambdaBool are fixtures demonstrating domain-independent rule composition, not a claim to implement Coil lambda semantics or capture rules. Call typing, argument annotations, function-type pattern premises, polymorphism and elaboration remain pending.

Premises can match structured function types and bind their components:

```
(Call ?result
  (callee (Fn ?argument ?result))
  (argument ?argument))
```

Patterns recurse through `Fn`; scalar leaves require exact type identity. The first occurrence of a variable, including inside a pattern, binds it. Later occurrences require equality, even within the same pattern, so `(Fn ?same ?same)` describes functions whose argument and result types agree. Variable slots are assigned by the first occurrence's source position, independent of spelling. A non-function where `Fn` is required returns `ExpectedFunction` identifying the child and actual type; scalar/component disagreement retains `Mismatch` and premise location.

Source-driven tests cover successful calls, argument mismatch, non-callable values, nested calls, repeated pattern variables and nested function patterns. This is structural matching of already concrete types. It does not implement metavariable unification, overload search, polymorphic instantiation or Coil's complete call semantics.

Scalar native lowering is now a schema-checked language:

```
(lower Expr
  (Integer (const value))
  (Boolean (bool value))
  (Add (add left right))
  (Choose (if condition yes no)))
```

Every sum variant needs exactly one lowering case. Operators validate their field names/types. `add` evaluates children left-to-right; `if` generates true/false blocks, a join and an SSA variable, evaluating each branch within its own block. Integer and boolean values currently use CIR i64. This is a limited scalar representation, not Coil's ABI/layout implementation.

The generated internal `lower-N` function requires an acyclic, fully checked graph with rules covering all reached variants. It does not recheck types or validate graph cycles; callers must successfully run the judgment first. Invalid references indicate a violated internal precondition. The source reader constructs acyclic graphs. No machine code should be emitted for rejected source.

`python3 tools/check-lowering.py` compiles source through generated reading, checking and lowering, then executes the retained direct native backend's result. Tests include both conditional arms, nested joins inside arithmetic and rejection before lowering, in debug/debug-checks/release host builds. The harness uses the retained backend's test image loader; this is acceptance scaffolding, not the eventual production lifetime-managed linker. Direct calls, lexical values, object output, runtime source/debug locations and general lowering types remain pending. `lower` contains no raw Coil escape hatch.

Lowering now supports lexical values:

```
(Variable (name))
(Let (let value body))
```

`name` resolves the binding declaration's reference field through the lowering context. `let` lowers its value children in the outer context, binds their resulting CIR values to the names declared for its body, and returns the body's value. Its final field must be that scoped body, and its value count must match the declared names. Other lowering operations cannot silently ignore a declared scope or reference. Context entries contain CIR value IDs, not source expressions, so uses share the initializer's result. Shadowing and leaving scope do not mutate outer bindings. An initializer's branch merge is completed before its value is bound; body branches receive the same dominating value.

The native suite includes shadowing, outer-name lookup in initializers, branch-local shadowing without leaks, and bindings initialized by conditional merges. It also generates 40 deterministic nested programs with an independent Python value oracle and executes them through the new generated frontend/lowering and retained backend in all three host build configurations. This does not cover side effects or calls yet; those must extend the same semantics tests as implemented.

`(Call (call callee argument))` lowers a unary scalar call. Callee and argument are lowered in source order. A zero-addend CIR symbol becomes a direct call; other callee values use an indirect call. The current ABI is one i64 argument and one i64 result. General signatures, aggregate passing and closures are not implemented.

`runtime/native.coil` now owns the direct-backend image boundary instead of using `tests.direct/load-compiled`. The caller supplies allocation storage for compilation state and image metadata, keeps it live through execution, unloads executable memory, then releases its arena. The adapter currently links only symbols defined in its image and supports the scalar operations exercised here; runtime helper resolution, recoverable link diagnostics, object output and general ABI handling remain required.

The call acceptance fixture registers an `increment` function's signature and symbol explicitly, checks and lowers both function bodies from source, links them in one image, and executes a caller containing a direct call plus a branch-selected indirect call. It verifies exactly two CIR call instructions even though a let-bound result is used twice. Source-level function declaration syntax and module orchestration remain to replace the fixture's registration code. Scalar and call suites use growing ScratchArena storage and explicit unload/release order.

Program declarations now derive function registration and body orchestration:

```
(node Function (name Text :key) (parameter Text) (body Expr))
(program Expr Function name parameter body Int Int)
```

There is one program declaration per generated module; its expression schema must have both a judgment and a lowering. The declaration selects a record's two distinct Text fields and expression body field. `program-functions` converts reader-produced record IDs into declarations, rejecting invalid IDs. `compile-program` collects all global signatures and symbols, rejects duplicate names, checks every body, and only then lowers and emits functions. Forward references are available during checking; parameters shadow global names. The returned image uses declaration order for symbol IDs. Callers own the scratch arena and executable-image unload lifetime, as for the native adapter.

`tests/program.coil.in` exercises forward calls, duplicate names, an invalid later body, wrong return types, and parameter/global shadowing. The native harness runs it in debug, debug-checks, and release. DSL checks reject duplicate program declarations, missing judgment/lowering dependencies, invalid fields, and unsupported signatures before publishing generated output.

This first program form only supports unary Int-to-Int functions. Its orchestration implementation is a fixed Coil generator template, counted as authored machinery; it is not yet the planned composable phase language. Global duplicate detection uses the schema-derived unique index. Global type and symbol contexts are now shared indexes; derive orchestration from reusable phase contracts before treating this as the final language architecture. The retained image registry still scans existing names during symbol registration. Full Coil syntax, macro expansion, general signatures, modules, effects, artifacts, and self-hosting remain outstanding.

Record fields can declare unique keys, for example `(label Text :key)` or `(serial Int :key)`. For each such field the schema compiler derives `index-N-F(allocator, rows, ids)`, returning a typed HashMap from field values to nominal row IDs. The selected ID sequence defines the scope of uniqueness; unselected rows do not participate. Keys may be Text, Int, or Bool. Multiple key fields define independent indexes, not a compound key. Sum variants may declare common keys: every variant must mark the same field names with the same scalar types, though field order may differ. Reference-valued and sequence-valued keys are rejected. For sums, generated API names and diagnostic field numbers use the first variant’s field positions.

Index construction checks IDs and reports `DuplicateKey(node, field, first, second)` with both original row IDs, or `InvalidIndexReference(node, id)`. The first duplicate in selection order determines the diagnostic. Failed construction releases the partial map. Successful maps belong to the caller and must be freed. `new-index-N-F(allocator)` creates an empty map; `insert-index-N-F(index, rows, id)` adds one row after validating its identity and checking uniqueness. A duplicate or invalid ID leaves that map unchanged and owned by the caller. Separate key indexes are independent, with no multi-index transaction. Text keys own copies and compare by content; IDs remain meaningful only for the original row table. An index is a snapshot: appending or editing rows does not update it, and building one does not make the mutable row table permanently unique.

Function-name fields must now declare `:key`. `compile-program` takes the selected function-record IDs directly, derives their unique-name index, converts the records, and proceeds to all-body checking. This removes the quadratic duplicate scan from the program template. The generic key mechanism is also exercised independently with 10,000 multi-key records, non-contiguous selections, duplicate provenance, repeated IDs, and invalid references. A separate 10,000-row sum fixture checks reordered fields, incremental and batch indexes, cross-variant duplicates, and unchanged indexes after failed insertions. It is part of schema-driven indexing, not yet a complete scope, namespace, or module binding language.


Checking and lowering now share `rewrite.scope/Scope[V]`, a small handwritten runtime kernel counted with the seed. A scope is a chain of borrowed lexical frames ending at either an empty root or a borrowed immutable HashMap. `scope-bind` creates a frame without changing its parent; `scope-global` wraps a map; `scope-lookup` returns the nearest local value or the indexed global value. Frames, borrowed names, and maps must remain live through lookup. Maps are populated before body checking/lowering and are not mutated while those phases run. The current kernel has no namespace/import semantics, scope cycles, or mutation/invalidation protocol.

Generated judgments use `Scope[TypeBinding]` for canonical type IDs and expression categories. Generated lowering uses `Scope[ValueBinding]`: `LocalValue` carries a CIR value, while `GlobalSymbol` carries an image symbol identity. A global lookup creates a CIR symbol at the use site. Global identities may be shared by every function; CIR values are function-local and are never stored in the shared global map. References in different branches are materialized in their respective blocks, avoiding accidental reuse of a value that does not dominate both branches.

Program compilation creates the two global maps once, borrows their roots for all bodies, and frees them after emission. It no longer builds a linked global context or emits all global symbols into every function. The native suite checks zero/used symbol counts with 2,000 globals, local/global shadowing and outer initializer lookup, and a 129-function forward-call program in all three host configurations. This establishes the removal of the repeated global setup, not a whole-compiler speedup: retained `image/symbol!` still performs a linear name scan per registration, and source-name resolution inside local scopes still walks lexical frames. Module indexing and stable binding identities remain required.

The seed also has an artifact-prerequisite language:

```
(phases
  (input declarations Declarations)
  (phase emit
    (needs (checked CheckedProgram))
    (makes (image NativeImage)))
  (phase check
    (needs (globals GlobalEnvironment))
    (makes (checked CheckedProgram)))
  (phase register
    (needs (declarations Declarations))
    (makes (globals GlobalEnvironment))))
```

A phase names required artifacts and their nominal representations, and one or more produced artifacts. Every artifact has exactly one source: an input or a phase. `rewrite.phase/schedule` resolves forward references, rejects missing or duplicate producers and representation disagreements, and derives a deterministic serial order. A dependency cycle is an error; no partial schedule is returned. Independent phases enter the ready queue in declaration order, and newly ready consumers follow their producer's edge order. All phases run; there is no output pruning. Resolving names uses hash indexes, followed by a linear traversal of the phase/edge graph.

The program compiler uses this contract to order its registration, all-body checking, and emission fragments at generation time. Its contract deliberately lists emission first; the derived output still checks every body before emission. The seed compiler itself is a second client: table definitions feed reader/index/judgment/lowering generation, and those outputs join before program generation. This replaces fixed scheduling in those two clients; their phase implementations remain Coil code or generated Coil fragments. The schema parser is still a prerequisite outside the seed-generation plan.

Representation names are checked nominal labels, not proofs that a phase implementation fulfills its contract. Stage implementations and their mapping to artifact storage remain trusted and handwritten; consumers reject unknown stage implementations. These plans describe finite single-assignment artifacts. They do not model mutation, capabilities, effects, failure recovery, dynamic discovery, expansion fixpoints, invalidation, cache identity, or typed artifact ownership. Those require further language mechanisms before this can represent Coil's full frontend protocol. Independent side effects must not be hidden in phases and assumed to be ordered merely by a ready-queue tie break.

Planner storage belongs to the supplied arena, including failed plans, and returned phase names borrow the contract text. `tests/phases.coil` checks reverse-declared dependencies, independent roots joining with multiple prerequisite edges, input-only plans, malformed contracts, absent/multiple producers, representation mismatch, duplicate phases, and self/mutual cycles. It runs in debug, debug-checks, and release as part of `tools/check-seed.py`; the native suite checks the generated program client.

Schema-checked source patterns now construct the same rows as constructor readers:

```
(syntax Expr
  (Integer (int value))
  (Boolean (bool value))
  (Variable (symbol name))
  (Add (list "+" (ref left) (ref right)))
  (Choose (list "if" (ref condition) (ref yes) (ref no)))
  (Let (list "let" (vector (symbol name) (ref value)) (ref body)))
  (Call (list (ref callee) (ref argument))))
```

`int`, `bool`, `text`, `symbol`, and `keyword` capture schema scalar fields; `ref` recursively invokes the referenced schema's surface parser. `list` and `vector` describe exact container shape, and a literal string in a pattern matches a source symbol. Every schema field must be captured exactly once with the right type; capture order may differ from schema field order. Every constructor currently needs one rule. Referenced schemas must declare syntax. Rules generate `surface-N(store, form)` functions; constructor `parse-N` functions remain available.

Root dispatch is ordered and committing. A literal-headed list rule claims that head before checking arity, so malformed `if` cannot fall through as a generic call. Scalar and container checks produce source diagnostics. Broader roots that would hide later rules are rejected, including symbols preceding booleans and a generic list preceding a literal-headed rule. Root references are rejected: recursion must consume a container before descending. This is not a backtracking PEG or a token grammar; it consumes `coil.reader` forms. A final `rest` capture supports repetition within a list or vector, as described below. Optional fields, multiple productions per constructor, quoting, arbitrary reader extensions, and full Coil syntax remain absent.

Generated readers validate shape and scalar captures before recursively constructing fields. They append children before parents and retain compact source origins for every row, including original source ID and span. They do not serialize or rewrite input text. As with constructor readers, a failed parse may retain previously appended children; release the input store/arena on failure if atomicity is required.

`tests/schemas/surface.syntax` also describes unary i64 `defn` with its parameter vector and result annotation. Native tests exercise calls, lets, conditionals, invalid syntax, source origins, and wrong-type rejection. `tests/syntax.coil.in` is an independent record/vector client with reversed field order. The legal source in `tests/surface-program.coil.in` executes through both the rewrite and installed Coil in all three host configurations. The installed compiler is an exploratory reference, not the pinned final compatibility baseline.

`tests/surface-function-value-invalid.coil.in` preserves the discovered bare-function regression: both implementations now reject it. `tests/surface-program.coil.in` exercises explicit `fnptr-of` and a subsequent call in both implementations. These comparisons cover the current unary i64 subset, not full function-pointer ABI, generic functions, closures, or macro expansion.


Judgments now distinguish an expression's category from its type. Ordinary premises require `value`. A premise can explicitly accept other categories, and a result can produce one:

```
(Call ?result (callee (in [value function] (Fn ?argument ?result))) (argument ?argument))
(AddressOf (Fn ?argument ?result) (function (in [function] (Fn ?argument ?result))))
(Place (as address ?type) (value ?type))
(Read ?type (place (in [address] ?type)))
```

Categories are open symbolic labels in the language specification. The seed checks qualifier shape, nonempty category sets, duplicate labels, and result form shape. Category qualification belongs to an expression premise, not inside a type constructor. Type-variable inference and structural Fn matching use the underlying type. A default result is `Typed`; a non-value result is `Classified(type, category)`. `CategoryMismatch` identifies the child node, actual category, and the consuming rule's span. Category failure precedes type matching; other child errors propagate unchanged. Lexical `bind` introduces values, and `lookup` preserves the category held by its scope binding.

Program globals bind their signatures as `function`; parameters and let-bound values use `value`. Call rules explicitly accept designators and function-pointer values, while ordinary operands and initializers reject designators. The `AddressOf` rule converts a function designator to a value with the same canonical signature. Its lowering uses the general `identity` operation because both representations use the same CIR symbol in this scalar prototype. The surface reader recognizes unqualified `fnptr-of`; the reference fixture imports that primitive. General namespace/macro resolution is not implemented by this surface rule.

Tests cover bare designators in initializers, arguments and conditions, rejection of taking the address of an ordinary value, direct calls, explicit pointer aliases and branch-selected pointer calls. The independent Place/Read rules exercise category production and consumption outside the function domain, with invalid-category provenance and malformed DSL cases. Categories currently have literal labels, not inferred category variables; places do not yet implement Coil's ownership or reference semantics.

A typed transformation maps source constructors to target expressions:

```
(transform Surface Expr
  (Integer (Integer value))
  (Unless (Choose condition no yes))
  (Bump (Add value (Integer 1)))
  ...)
(transform SurfaceFunction Function
  (SurfaceFunction (Function name parameter body)))
```

The ellipsis above stands for the required remaining constructor rules; it is not syntax. Every source constructor must have exactly one rule. Target expressions consist of source-field names, typed scalar literals, and nested target constructors. Constructor names, arities, and field types are checked before generation. Every reference field requires a declared source-to-target map, including same-schema references; traversal is derived from those maps. Scalar values are preserved and Text is copied into the target intern pool. No raw Coil escape hatch is accepted in a transformation term.

Maps read one Store and append to a distinct target Store. Source and target schemas may overlap, including identity maps; references are always remapped into the target. Passing the same Store as input and output is rejected. A generated module permits one map per source/target schema pair and result cardinality; single-result and sequence-result maps can coexist. Maps between different node schemas can call each other, as expression and function-declaration maps do in the fixture.

`transform-state-new(allocator, input, target)` borrows two distinct Stores, snapshots input row counts, and creates a memo table for each map. `transform-S-T(state, sourceId)` returns a nominal target ID or a structured error. Keep this state across all roots in a compilation unit to preserve sharing; repeated roots create no additional target nodes or traces. Source growth, out-of-range traversed IDs, missing source origins, and cycles are rejected. Visiting markers unwind on failure, so an unsuccessful root does not poison later calls. Successfully built children and their memo entries may remain after a failure; output construction is not transactional.

The state is tied to its input and target Stores. Source rows and origins must remain unchanged while it lives, and target rows must remain append-only. Row-count checks detect growth, not arbitrary in-place edits through exposed arrays. This is an immutable-input contract, not a static ownership proof. `transform-state-free!` releases memo tables and its document-transfer index. Target rows, text, documents, and traces belong to the target Store and survive input teardown. The caller still owns allocator lifetime; sharing an arena ties its physical reclamation to both Stores. Public arrays can bypass these invariants. Typed phase ownership and transactional publication remain required.

Every constructed target node receives the current source node's compact origin, and a `source/Trace` in the target Store records source/target schema and node IDs plus the transformation rule span. Nested target constructors inherit that rule's source origin. Recursively mapped references preserve their own source origins. Documents are copied once per source ID per transformation state; conflicting source identities, missing documents, and invalid spans are errors. Traces retain numeric source-node identities, not source rows; multi-stage ancestry and persisted DSL rule source documents remain unimplemented. Structural memoization does not memoize runtime expression evaluation or provide binding-aware substitution, fresh identities, hygiene, effects, or a fixed-point rewrite strategy.

`tests/schemas/transform.schema` defines a surface representation with `unless-else` and `bump`, and maps it into the core representation, which contains neither constructor. The generated function map recursively uses the expression map. `tests/transform.coil.in` checks shared subgraphs, cached roots, provenance, cycles and retries, invalid references, source growth, and missing origins. Its native case parses surface declarations in a separate arena, transforms them, poisons and frees source storage, then checks and executes the core program while verifying retained source documents. `tests/transform-owned.coil.in` exercises same-schema copying with offset target IDs, content interning, real malloc-backed teardown, alias rejection, and source-document errors. The native harness also verifies that source declaration IDs cannot be passed directly to the core compiler. This is a context-free dialect normalization test, not the external reader/metaprogram compatibility gate.


Sequence-result maps express omission, introduction and ordered splicing:

```
(transform Declarations (many Function)
  (Define (items (Function name parameter body)))
  (DefineAlias
    (items
      (Function alias parameter (Call (Variable name) (Variable parameter)))
      (Function name parameter body)))
  (Ignore (items))
  (Group (items (spread left) (spread right))))
```

Each source constructor still has exactly one rule. A sequence result can be `items`, containing ordinary target expressions and `(spread source-field)` forms, or a sequence-valued field mapped elementwise by a single-result map. A spread requires a matching sequence-result map; a reference inside a target constructor requires a single-result map. Cardinality is checked before generation, without implicit conversion or dropping extra results. Every result constructor gets the original source node's origin and rule trace. Empty results create no target rows. Introduced names follow the rule's explicit Text expressions; there is no fresh-name or hygiene policy here.

The generated `transform-many-S-T` returns a nominal `NTSeq` handle into the target Store. Memoization preserves the result sequence and shared target IDs; splicing the same child twice repeats its IDs in the logical output without reconstructing its nodes. A sequence survives transformation-state and input-Store release. `sequence-size-N` and `sequence-item-N` check handles and positions. `sequence-materialize-N` appends the ordered result to a caller-owned ArrayList once at a sequential-consumer boundary. Sequence IDs are nominal by node schema, but remain local to their target Store.

`rewrite.sequence` stores immutable leaf segments and joins over existing segments. Joining copies child handles, not descendant values. Empty children are omitted and a single nonempty child reuses its handle. Length is cached and checked for i64 overflow before a join is published; generated maps propagate `TransformSequence`. Random access follows segment paths; materialization uses an explicit stack and takes time proportional to the traversed output structure. A compact DAG may describe an enormous output, so successful construction is not a promise that materialization fits memory. Runtime allocation failure still follows Coil allocator behavior. Public array mutation and aliasing output with internal storage violate the low-level runtime contract.

Validation includes 10,000 nested joins with 10,001 stored values, growth-stable handles, a compact sequence of logical length 2^62, and capacity/invalid-handle rejection without partial join publication. An independent schema-map fixture checks empty results, two outputs per leaf, shared children, separate single/many maps, input teardown, and retry after capacity errors. The native declaration fixture introduces an alias before its implementation, preserves source order through nested groups, omits an ignored form, compiles and executes both introduced functions, and rejects an introduced duplicate name through normal program indexing.

This is context-free one-to-many normalization, not staged Coil macroexpansion. Binding-aware substitutions, fresh identities, effect contracts, dependency discovery and expansion fixpoints remain required. Node transformation recursion still uses the host stack; sequence mapping and materialization use explicit stacks. The sequence runtime is handwritten Coil machinery counted toward the authored budget, pending self-description.


Schema fields now support `(many Node)`:

```
(node SourceProgram (declarations (many Declarations)))
(node CoreProgram (functions (many Function)))
(syntax SourceProgram
  (SourceProgram (list "module" (rest declarations))))
(transform SourceProgram CoreProgram
  (SourceProgram (CoreProgram (items (spread declarations)))))
```

The generated row field has the element schema's nominal sequence type. Constructor readers accept a vector of constructor forms for it. Surface patterns use `(rest field)` as the last child of a list or vector; it captures zero or more remaining forms and parses each through the element schema's syntax. Fixed prefixes still require their full arity. A rest capture elsewhere, a single capture for a sequence field, and missing element syntax are rejected before output. Sequence fields currently contain node references, not primitive scalars or nested sequence types. Keys remain scalar fields, and judgment/lowering operations that require one child reject sequence fields.

A sequence-valued source field used directly as a target sequence expression maps each element using the declared single-result map. Inside `items`, spreading that field instead uses a sequence-result map for each element and concatenates the results. This distinction preserves result cardinality explicitly. Generated `sequence-transform-S-T` and `sequence-transform-many-S-T` wrappers supply the element operation to a shared generic Coil traversal; they never flatten the input just to map it. Per-map segment memo tables preserve DAG sharing, reject input segment growth and cycles, and reset visiting states on failure while retaining completed children. The traversal uses an explicit stack, including failure cleanup. Inputs and targets must remain distinct and input segments immutable; public backing arrays can bypass the contract.

The native fixture now parses an arbitrary-length module declaration list, including nested and empty groups, and transforms it into a core module with a function sequence field. The independent vector-record fixture parses constructor and surface forms, rejects malformed containers/elements/arity, and maps a shared sequence with logical length 3 × 2^60 while retaining only three target element rows and fewer than 70 sequence segments. Text remains valid after input storage is poisoned and freed. The runtime suite maps 10,000 nested joins, injects an element error, retries using completed memo entries, and checks cycle cleanup and source-growth rejection.

These lists provide data and traversal for declaration collections. They do not yet define binding, simultaneous declarations, imports, expansion rounds or compile-time execution. Sequence judgments and lowering operations need their own semantic rules rather than treating a list as one expression.


Binding declarations are a shared semantic input:

```
(bindings Calc
  (Read (reference label))
  (Outer (scope body label))
  (Parallel (scope body left-name right-name)))
(judgment Calc
  ...
  (Parallel ?body
    (left ?left) (right ?right)
    (body ?body (with ?left ?right))))
(lower Calc
  ...
  (Parallel (let left right body)))
```

Ellipses stand for the other required cases. A `reference` annotation selects one scalar Text field per constructor. A `scope` selects a node-reference child and one or more scalar Text fields whose names are visible only while processing that child. Constructors without annotations remain unscoped. Duplicate schema/constructor declarations, duplicate child scopes, repeated name fields within one scope, unknown fields and invalid field types are rejected. Names are installed in listed order; if distinct name fields contain the same Text, the later binding shadows the earlier one. This is ordered lexical shadowing, not a uniqueness rule for parameter declarations.

The seed parses and validates this binding model once alongside schemas, then passes it to judgment and lowering generation. The generation phase contract names the model as an input to both consumers. Checking supplies type payloads with `with`; lowering supplies value-child fields with `let`. The current lower operation evaluates all value children left-to-right in the outer context before extending the body context. The type checker similarly requires each payload type to be available before checking the scoped child. Consumer contracts reject missing/extra payloads, undeclared lookups, unconsumed scoped children and scopes that the lowering operation cannot implement.

`tests/schemas/parallel-bindings.schema` is a second language with a two-binding form whose initializers see the outer scope. Native tests distinguish that behavior from sequential binding, check shadowing and sibling isolation, and check mixed Int/Bool payloads. A separate probe changes only the binding declaration's name order: both the inferred result type and native result change accordingly, without editing judgment/lowering rules. Existing unary Coil-shaped let tests and installed-Coil source comparisons remain unchanged.

The binding model separates lexical topology from client-specific payloads; it does not prove that arbitrary typing rules and lowering rules assign equivalent payload semantics. Names still resolve through Text contexts in each consumer. Standalone resolution now derives result-local declaration identities as described below; these consumers do not use them yet. Namespaces/imports, forward/recursive declaration groups, binding-aware transformation, renaming/substitution and capture rules remain required. Scope annotations on sequence children can be represented, but the current single-child judgment/lowering operations reject them; sequence semantics need their own operations. This is not a general constraint engine or full Coil name resolution.

## Generated lexical resolution

The existing `bindings` declarations also derive a resolver when the module has reference or scope annotations. `resolve-N(allocator, store, root-id, globals)` returns `Result resolution/Resolution resolution/ResolveError`. `globals` is an ordered list of Text names; duplicate global names are rejected. Resolve each complete lexical root with its required globals. The resolver does not infer imports or program signatures.

A result contains declarations and occurrences. `BindingId` indexes a declaration in that result only. Each declaration identifies its owning occurrence and schema field; globals have owner and field `-1`. Each occurrence identifies its schema, source row, parent occurrence, incoming field and sequence position, plus an optional resolved reference target. Root parent/field/item and non-sequence item positions use `-1`. These source row coordinates allow clients to recover origins from the original Store.

Identity follows occurrences, not storage rows: a shared row visited in two lexical positions has two occurrences, and a shared binder visited twice introduces two declarations. A name field visible in several children of one occurrence introduces one declaration shared by those scopes. Declaration IDs follow schema field order; scope installation follows the declared name order, so later names shadow earlier names even when their field order differs. Unscoped children inherit the outer context, including binder initializers. Sequence elements inherit their containing child scope and retain their individual positions.

Generation derives traversal across records, sums, cross-schema references and node sequences. It produces direct typed calls and scope frames, with no runtime rule interpreter. Active row indexes reject a cycle on the current traversal path while allowing repeated DAG occurrences. Unknown references, invalid row/sequence identities, cycles and duplicate globals return structured errors. A failed public resolution releases its partial result and scratch indexes; a successful caller releases the result with `resolution/release!`.

Names in declarations and errors borrow the Store or supplied global-name storage. These inputs must remain alive and immutable while those names are used. Results are separate resolutions: IDs must not be compared across results or reused after release. Generated worker functions and mutable result arrays are internal mechanisms, not a checked ownership boundary.

`tests/resolution.coil.in` checks shadowing of a shared reference, repeated binder occurrences, the same declaration visible in multiple children, scoped sequences, declaration-order versus scope-order behavior, globals, failure paths, and growth to 30,001 occurrences and 10,001 declarations, using the malloc allocator. The fixture runs in debug/debug-checks/release.

This establishes an explicit resolution artifact. Typing, lowering and general schema maps do not consume these identities yet; typing and lowering still use their own name contexts. The derived alpha-copy operation described below is the first transformation consumer. Macro hygiene, persistent identities, namespace/import resolution and recursive declaration groups remain unimplemented. Node traversal uses the host stack; sequence traversal currently performs indexed access to each element, so deeply joined collections can repeat path work. There is no context-sensitive memoization or full-compiler performance claim. The runtime and generator remain authored Coil machinery counted toward the source budget.


## Identity-directed alpha copying

Binding annotations also derive `alpha-N(allocator, input, target, root-id, globals)`. This operation resolves the input, assigns each local declaration a distinct name, and copies the root into a distinct target Store. It returns `Result AlphaN AlphaError`; `AlphaN.root` is the nominal target root, and `AlphaN.rows` maps each source lexical occurrence to its target row index in that occurrence's schema. The caller frees this mapping array. The operation itself releases resolution and scratch storage.

References are rewritten using their resolved declaration IDs. Binder fields use the names of their own declarations. All global names remain unchanged, and generated local names avoid every supplied global name. Names start with `__coil_local_` and a deterministic serial; this spelling is an implementation detail, not a cross-session identifier. Unannotated Text fields are copied verbatim by content. Field and sequence order remain unchanged, as do scalar values and constructor kinds.

The copy follows lexical occurrences rather than memoizing source rows. A shared reference under different binders therefore becomes distinct target rows with the appropriate names. It also expands repeated binder occurrences into distinct declarations. This deliberately gives up storage sharing; it does not change how often the source language evaluates those occurrences. The returned correspondence and an independently resolved target can be used to compare binding relationships. The fixture verifies reference targets and declaration owner/field identities, not just successful name lookup.

Target Text, origins and immutable source documents are copied into target-owned storage. The source Store can be poisoned and released before using the result. The returned row mapping refers to source occurrence numbers; it is not the ordinary schema-map rule trace and does not retain the source resolution's borrowed names. Existing target rows remain valid. Names are fresh within this resolved root relative to its globals; separately renamed roots cannot be combined under new scopes without additional identity/visibility work.

Aliased Stores, failed input resolution, missing origins and source-document conflicts are structured errors. A name field annotated as both a reference and a binder cannot independently receive both declaration names; alpha copying reports `AlphaOverlappingRole` for that occurrence. Such schemas remain valid for resolution. On failure scratch and mapping arrays are released, but target-owned text/documents and any already copied subtrees can remain, as with current schema maps. The caller must not publish a failed root. This is not transactional target mutation.

The alpha fixture checks reserved-global collisions, repeated shared references, declaration/occurrence correspondence, independent storage after input teardown, and failure variants. The native suite alpha-renames its 40 seeded closed-expression cases before checking, lowering and execution against the same expected values. Both suites run debug/debug-checks/release.

This is a shape-preserving binding-aware operation derived from the binding DSL, not a general hygienic macro or substitution language. General maps, introduced declarations, insertion under new scopes, module identities and persistent freshness still need explicit binding transport. Typing/lowering still use Text contexts. Copy traversal uses the host stack and indexed sequence access, like the current resolver; no compile-time/memory improvement is claimed, and expanded occurrences can use more memory than the input DAG.


## Declared host functions

A program may append explicit host declarations:

```text
(program Expr Function name parameter body Int Int
  (host increment Int Int)
  (host double Int Int))
```

Each declaration introduces a global function designator with the same unary Int-to-Int signature supported by the current program language. Calls and explicit function-pointer conversion use the existing typing/lowering rules. Duplicate host declarations are seed errors; collisions with program definitions return `DuplicateFunction` before emission. Parameter and lexical shadowing still follow ordinary binding rules. Host symbols follow program definitions in the image, preserving existing function symbol IDs. Declared hosts remain required even when unused; there is no import pruning yet.

`rewrite.native/HostFunction` contains a name and a typed C function pointer `(fnptr (cc/C) [i64] i64)`. Supply a list to `native/load-image-with`, which returns `Result jit/Loaded native/LinkError`. The loader indexes the image's symbol names, validates symbol-table lengths/uniqueness and every supplied binding, and only then maps executable code. Missing, duplicate, unknown, null and locally defined import bindings are errors. This is symbol-linkage validation, not a complete verifier for arbitrary image bytes or relocation arrays.

Callback addresses are supplied explicitly for each loaded image. They are never resolved through process-global symbol lookup, and must remain valid until that image is unloaded. Two live loads can bind the same imported name differently. Generated code has the capabilities of the callbacks provided by its caller; no effect model, Code store or semantic-query context is implied by this API. The no-import `native/load-image` convenience wrapper now uses the checked path and panics on unresolved/malformed symbols; callers needing recoverable diagnostics use `load-image-with`.

The native suite checks direct and indirect calls, source/host name collisions, invalid host declarations, typed callback rejection, missing/duplicate/unknown/local/null bindings and independent linkage of simultaneously live images in debug/debug-checks/release. The generated program calls a host helper through an ordinary source helper and an explicit function pointer, producing the expected native result.

This is a prerequisite for explicit compile-time runtime operations. Program-visible host signatures remain unary i64; callbacks may now carry the explicit context described below. This is not general FFI or Code-valued staging. Multi-argument/aggregate ABI contracts, syntax ownership, stage declarations, retained semantic capabilities and language resumption remain outstanding. No fallback to the reference compiler is involved in executing these generated programs.


## Owned reader syntax

## Context-bearing native callbacks

`native/ContextFunction[C]` pairs a named callback of type `(fnptr (cc/C) [(ptr C) i64] i64)` with a borrowed `(ptr C)`. `load-image-with-contexts` accepts a list with one context type, but each binding can reference a different context object. The generated program still sees its declared unary Int-to-Int host function.

The loader first validates all names and callback addresses through the same linkage planner used by ordinary host functions. It then emits a small CIR wrapper per import: capture the supplied context/callback addresses, accept the unary argument, call the host function with context plus argument, and return its result. These wrappers use the retained native backend rather than handwritten machine-code encoders. Pointer transport uses the scalar register ABI of the retained 64-bit targets. Validation tests currently execute on this Mac; this change does not establish cross-target ABI parity.

The returned `ContextImage` owns the main executable mapping and an optional callback-wrapper mapping. Use `native/unload-context-image!` to unload both, with the main mapping released first. Obtain program entry addresses from its `program` field. The caller's allocator-backed image metadata, callback code and stable context objects must outlive the loaded image. Contexts are borrowed, not copied or freed, and their synchronization remains the caller's responsibility. Import-list storage can be released after loading; wrapper symbol names borrow the original program image's names.

There is no ambient current-context slot. Different live images retain their own captured pointers, and a callback can enter another image and return without replacing the original context. Tests use reversed import order, distinct mutable contexts, nested native re-entry, null/missing callbacks and compile-time callback-signature rejection. They run in debug/debug-checks/release alongside the existing native suite.

This establishes explicit callback context transport. It does not turn an integer into a validated Code handle, retain a syntax store automatically, implement a semantic-query capability, or run the staged protocol. Invocation handle ownership, stale/foreign handle rejection, Code operations, cumulative declarations and language resumption remain required. Context wrappers are counted runtime machinery; no compile-time or memory improvement is claimed.

## Invocation-owned native syntax handles

`rewrite.invocation` owns a `code/Syntax` store and a bidirectional mapping between its syntax rows and positive native integer handles. `read-one!` reads exactly one root into that store. `child!` selects the first or last element of a list/vector, and `integer` projects an integer value. Repeated publication of the same row returns the same handle. All native-facing operations validate the handle against the supplied invocation before accessing a row.

A shared atomic identity supply assigns handles monotonically and refuses exhaustion instead of wrapping. It is shared identity allocation, not a current-invocation variable. The uniqueness scope is one loaded instance of this runtime; independently loaded copies must not exchange these handles. Zero is reserved for callback failure. These values are validation tokens, not a security sandbox or persistent artifact identities. Internal `publish!` accepts an ID from the invocation's own store; a raw store-local ID carries no provenance proof.

`invoke-code!` validates both the argument and returned handle. `invoke-value!` validates the syntax argument but returns an arbitrary scalar, including zero. Both reject null entries and same-invocation re-entry. Native callbacks record the first failure and return zero; subsequent callbacks do no work until control returns to the entry boundary. A new valid invocation clears that error. Entry addresses must otherwise be valid executable functions supplied by the loader; the runtime cannot validate arbitrary non-null machine addresses.

`close!` releases owned syntax and handle maps, is idempotent, and refuses to close an executing invocation. A closed invocation rejects all handles. Reinitializing its storage creates fresh handles, so old values do not become valid merely because row numbers are reused. Loading more source while an invocation is executing is also rejected. Context objects must remain at a stable address while their native wrappers exist; unload those wrappers before releasing the object itself. Separate invocations may nest, but access to an individual invocation requires caller synchronization. Atomic identity allocation does not make the syntax store or maps concurrently mutable.

The runtime and native fixtures cover foreign/stale handles, canonical row publication, scalar zero versus invalid handle zero, identity exhaustion, malformed input, empty containers, null entries, callback error recovery and same-invocation re-entry. Native selection executes through generated program rules and retained-backend context wrappers. This remains a small read-only syntax API over a scalar ABI: builders, syntax promotion, semantic queries, richer Code typing and cumulative staging are not implemented.

## Cumulative phase programs and bootstrap reader resumption

A program declaration may include `(cumulative)` alongside its host declarations. This derives a `ProgramHistory`, `program-history-new`, `program-history-free!`, and `extend-program`. A history borrows one stable Store; its accepted declaration rows must remain immutable, and new rows may be appended. An extension compiles the accepted prefix plus the proposed declarations, using the ordinary program name, signature and body checks. Only success appends the new IDs to history. Duplicate names and invalid bodies leave the accepted prefix unchanged. Duplicate or malformed cumulative policies are rejected during language compilation.

Every successful extension produces a fresh native image containing the cumulative phase program. This supports later entries calling earlier helpers without retaining the earlier executable mapping. ## Bounded effect protocols

`languages/protocol.schema` defines the protocol grammar; its generated parser and key indexes are used by `seed/protocol.coil`. A protocol module contains an optional module declaration and exactly one protocol, with no schema declarations mixed in. For example, `languages/staging.protocol` declares routing, installation, invocation and resumption as separate states:

```text
(protocol
  (budget requests 64)
  (start route)
  (finish complete)
  (state route
    (on Done complete)
    (spend Request requests install))
  (state install (on Ready invoke))
  (state invoke (on Returned resume))
  (state resume (on Again route)))
```

An `on` edge selects its target after the state's handler returns that event. A `spend` edge first checks and consumes one unit of its named budget, then selects its target. If the budget is exhausted, the target handler is not called. The source handler has already run; effects are not rolled back. Completion is checked before calling another handler, so a successful final outcome remains successful at an exact budget boundary. Counters start fresh for every `run`.

The seed compiler uses a compilation arena for its parser, indexes and intermediate graph storage. It resolves all state and budget names, checks unique states/budgets and per-state outcomes through generated indexes, rejects unreachable states, and requires every nonterminal state to have an outcome. It removes spending edges and requires the remaining graph to be acyclic. Thus every control-flow cycle spends a finite budget. This bounds protocol transitions assuming handlers return; it does not bound a handler's own time or memory. A protocol needs one start, one finish, and at least one effect state. Budgets may be zero; acyclic protocols need none. Names use ASCII letters initially, followed by letters, digits, hyphens or underscores.

The compiler emits an `Event` sum with `Event-NAME` constructors, a typed `Handlers[C E]` record containing one `step-STATE` C function pointer per effect state, and `run(context, handlers)`. Handlers return `Result Event E`. The driver uses compiled state dispatch and direct typed calls; no protocol parser or transition-table interpreter runs in the generated application. Success is `Ok true`. Failure identifies a handler error, an event not declared for the current state, or an exhausted budget. Generated `state-name`, `event-name` and `budget-name` functions give readable labels without relying on numeric declaration positions.

The standalone protocol tests exercise this request-count driver. The native staged-chain fixture now uses the owned before-expand runner described below. Its effect adapters still perform guest-tag discovery, construct phase declaration batches and bridge to the compiler/JIT; they remain fixture code. The 64-request model is retained as a language-mechanism example, distinct from the reference's shared 16/64 round counter. Captured boundary evidence and the owned adapter below establish that accounting without claiming full source-level expansion parity.

`tools/gen-schema.py` now regenerates the schema grammar, owned syntax grammar, protocol grammar and staged protocol program, then checks their fixed point under an isolated seed rebuild. This is language-toolchain regeneration with a host Coil dependency, not full compiler self-hosting. Protocol coverage includes independent retry/poll budgets, acyclic operation, zero/exact/exceeded fuel, repeated fresh runs, callback failures, unexpected events, invalid definitions and callback signature rejection.

## Shared budgets with outcome-specific ceilings

`(spend-within Event budget ceiling target)` consumes the same counter as `spend`, but refuses the transition when that counter is already at the stated ceiling. A ceiling must be nonnegative and no greater than the budget's declared limit. It is not a separate counter and does not reset the counter. Like `spend`, it is a bounded edge for cycle validation, and the source handler runs before its outcome is checked.

This expresses the captured before-expand accounting kernel in `languages/before_expand.protocol`: a round computes candidate forms and returns `Equal`, `ChangedPlain`, or `ChangedStage`. Equality finishes without spending. Plain changes use ceiling 16; staged changes use the same counter's limit 64. The accept handler publishes the candidate only after the guard passes. The generated model reproduces the changing-round reference traces, including mixed stage progress, through `tools/check-expansion-policy.py`.

This model does not implement the round's compiler effects or initial whole-form normalization. The reference probes demonstrate why module-shaped Code equality alone is insufficient: an unchanged module projection can still correspond to a changed first whole-form round. The protocol grammar, staging mechanism model and before-expand guard model now regenerate alongside the schema and syntax grammars under the isolated seed check.

### Schema-derived equality

`(equality Schema)` derives `equal-N` and `equal-N-with` entry points for the named schema. The generated worker compares scalar fields, sum variants, referenced rows and ordered sequence contents across two stores. Sequence segmentation is not observable. Float bits in the syntax schema are integers, so signed zero and NaN payload distinctions survive comparison.

`seed/equality_runtime.coil` owns an explicit traversal stack and a memo keyed by `(schema, left row, right row)`. Each encountered row pair is evaluated once; storage sharing on either side does not define equality. Active pair cycles, invalid row IDs and invalid sequence roots return typed errors. A false result can short-circuit before unrelated invalid data: this is not a whole-store verifier. Sequence internals rely on the sequence builder's invariants. The stores and metadata must remain immutable throughout comparison.

The optional typed metadata callback runs once per new row pair, after reference validation. `code/equal?` compares structural syntax; `code/source-equal?` additionally checks scope and definition module at every node, matching the reference's source-reuse predicate. Neither compares locations, transport flags, expansion context or reader-node identity. Missing required metadata is an error, including when comparing a row with itself.

The runtime avoids recursion for row graphs and shares completed pair results. Its space cost includes visited pairs and pending edges. Sequence fields currently materialize their logical elements before enqueueing pairs; compressed sequence joins are not compared in compressed time. This is an explicit performance limitation to measure against expansion workloads, not a claim of whole-compiler improvement.

`tests/equality.coil` covers the syntax predicate distinction, raw float bits, tags, pair-sensitive memoization, a 25,000-level shared DAG, cycles and recovery. `tools/check-equality.py` independently generates a record schema and exercises cross-schema fields, Int/Text/Bool, sequence segmentation, malformed edges and declaration diagnostics in default, checked and release configurations. The existing seed gate runs both. Production whole-form round effects remain to be connected to these comparisons.

### Owned expansion generations

`FormSequence` in `languages/code.schema` represents ordered whole-form roots. Its derived equality uses one pair memo across roots. `rewrite.rounds` owns current and candidate generations, each containing independent syntax storage and separate runtime/new-stage root sequences. Its typed effect callback receives borrowed current forms and fresh candidate storage, performs one round's work, and returns success or an error. Successful effects must supply valid runtime forms and the batch of newly introduced stage declarations; the adapter does not parse stage markers or validate declarations on their behalf.

The adapter computes structural equality from the generated schema, classifies stage progress from the new declaration batch, and passes those outcomes to `before_expand.protocol`. Only its accepted transition swaps candidate and current ownership. Equality retains the old generation, including its metadata. Exhaustion and callback/comparison errors retain accepted forms and keep the candidate alive for inspection and borrowed diagnostics until the next run or close. External compilation/execution effects have already happened and are not rolled back. The effect's `Ok` boolean is a success payload, not a progress flag; progress comes from the declaration sequence.

A run rejects same-session re-entry and close during a callback. Close is idempotent; running a closed session fails. Session structures must not be copied, and callers must not mutate/free current storage or retain callback borrows. A new explicit run starts fresh guard accounting on its existing current generation. This is not an incremental session policy or a replacement of accepted live code.

`tests/rounds.coil` covers actual syntax changes, later-root changes, changed root count, equal metadata-only changes, stage-only equality, all captured changing-round limit patterns, callback/comparison failures, re-entry, reuse and ownership. The native staged-chain fixture now uses this runner: two native helper increments publish two generations, and a third structurally equal round finishes without publishing. Runtime execution still returns 42 with only its runtime entry in the image. The simpler request protocol remains independently tested as a protocol-language example.

Guest routing, stage-source selection, compilation adapters and source normalization remain fixture work. These batches have no loader module-tag table yet. Full multi-module normalization, marker routing, semantic model exposure and ordinary macro expansion remain incomplete; the runner is a production ownership/guard adapter, not a claim of full before-expand compatibility.

### Declared metadata policies and stage datum

`(context-policy Name Sum Record (Variant (field value)...)...)` declares metadata edits selected by a syntax constructor. Values are typed Int/Bool/Text literals or `fresh` for an Int field. Unmentioned fields and variants retain their values. The compiler rejects unknown schemas, variants or fields, duplicate policies/rules/fields, invalid generated names and incompatible values. It emits `context-NAME` and `context-NAME-fresh?`; the caller supplies the fresh integer once per selected occurrence. The pure policy does not allocate identities or choose their lifetime.

The `stage-datum` policy in `languages/code.schema` expresses the reference's separate-compilation context removal: symbols get scope zero, empty definition module, origin 5 and a fresh identity; lists/vectors get a fresh identity; all other fields and leaf kinds remain unchanged. It applies inside quoted syntax too: stage isolation is a copy of a compilation unit, not request discovery. `code/stage-datum!` combines that policy with the existing generated structural transform. Its bootstrap identity supply is the reader's same-session `next-node-id`, not a cross-session identity registry.

Stage isolation must copy occurrences, because a shared input symbol/container receives a fresh identity at each occurrence in the reference. Generated transform state now has a `sharing?` option, true by default. False disables completed-row and completed-segment reuse while retaining active-cycle detection and error cleanup. `sequence/map-mode!` implements the corresponding segment traversal; `sequence/map!` retains its compact default behavior. Inputs remain immutable and each traversal starts with fresh memo state. Occurrence-sensitive copying can grow with the unfolded graph, and generated row recursion still uses the host stack; this is no general performance improvement claim.

`code/promote-with!` applies a typed metadata callback to each generated provenance record, instead of assuming a source row has one destination. It owns text before invoking the callback; returned text must retain a suitable lifetime. Ordinary `promote!` selects identity metadata and preserves DAG sharing. `stage-datum!` selects occurrence copying and the declared stage policy. Both preserve source documents and report malformed graph/context failures without publishing a root.

`tests/stage-datum.coil` checks symbol isolation, unchanged non-symbol metadata and leaf identities, repeated rows behind a shared sequence join, distinct occurrence identities, source independence, cycles and retry. `tools/check-context-policy.py` independently generates a different schema with Bool/Text/Int edits and checks declaration diagnostics. Stage splitting with module tags is now implemented below. Request routing remains to be implemented; the native chain fixture still selects its phase source in fixture code.

### Borrowed syntax views and stage partitioning

Every syntax declaration now also generates `view-N(a, form) -> Result (Option SyntaxView) Diag`. No matching root yields `Ok None`; a matching root commits to its pattern and malformed fields/arity produce a diagnostic. A successful view records its variant and captures in schema-field order. Each capture borrows a reader form; a rest capture names its container and starting index. The caller owns the capture array. Views validate the declared shape but do not recursively parse `ref` or `rest` contents; full `surface-N` construction still does. Both use the same pattern compiler and guards.

`StageDeclaration` in the syntax schema declares `(stage MARKER FORM...)`. `rewrite.stage/split` uses its generated view to partition a batch of `Tagged` roots. Only top-level list declarations are removed. Each body form retains the declaration's `Option Text` module tag and uses the declared stage-datum copy policy. Runtime forms preserve their metadata and shared rows. Empty stages register markers without introducing forms. Marker lookup is compilation-wide, independent of module tags; duplicates preserve first-seen order. Previous markers and all new names are copied into the successful result, which owns runtime/stage syntax, documents, module strings and marker strings independently of the input.

Splitting uses one scratch projection cache and two generated copy states for the whole batch, rather than allocating source-sized state for every root. Runtime copies share completed results; stage copies preserve distinct occurrence identities. Borrowed reader projection is still a bootstrap adapter and row traversal remains recursive. No full-compiler performance claim follows from this allocation structure. A supplied promotion state is valid only for its original stores and fixed policy, and must be discarded after any error; the splitter aborts and releases its private output on failure.

The native chain fixture now wraps selected phase source in stage declarations, partitions it through this production splitter, and compiles the isolated body forms. Its cumulative marker history is owned independently of round candidates. Source selection and request routing remain fixture logic. The splitter does not validate stage entry signatures, reject duplicate definitions, resolve imports or execute requests; those belong to the subsequent compilation/routing stages. Loader-wide module normalization and ordinary macro expansion remain outstanding.

`tests/stage-split.coil` covers order, top-level-only classification, nested stage/quote/vector data, empty stages, cumulative markers, anonymous versus named-empty module tags, distinct stage identities, shared runtime roots, source independence and malformed declarations. `tools/check-syntax-views.py` independently exercises capture reordering, variants, shallow references, empty tails and committed errors in all three configurations.

### Declared request walks and entry selection

The `walk` language declares opaque list heads and excluded container prefixes. `(opaque-list "quote")` stops at that list; `(prefix "defn" 4 (keyword 2 "cc" 6))` starts child discovery at 4, or at 6 when position 2 contains keyword `cc` followed by its value. Prefix rules apply to both lists and vectors, matching the inspected reference helper. Scalars are opaque and other containers begin at zero. Names/heads must be unique within their scope; malformed offsets, keyword pairs and rule forms are rejected before output. Generated `walk-NAME` returns typed `KeepSyntax` or `VisitChildren` decisions.

The syntax schema declares `StageEntry` (symbol or ordinary string) and `StageRequest` (marker, entry, raw argument tail). `rewrite.requests/inspect` combines these views with `walk-stage-requests`, a caller-supplied compilation-wide marker set and an available-entry set. Quote opacity takes precedence even if `quote` is a marker. Otherwise a list headed by a declared marker takes precedence over prefix exclusion. Undeclared list heads never become requests merely because an entry exists. Entry names containing a dot are already qualified; other names use the declaration's optional module tag, including the distinction between anonymous and named-empty tags. Lookup errors retain both written and qualified names plus call origin.

`find-first` uses an explicit worklist to return the leftmost outer request, leaving all its arguments untouched. It excludes declaration prefixes using the generated policy. It expects a valid acyclic reader graph, as produced by the checked owned-syntax projection, and does not memoize repeated occurrences. Captures/site pointers borrow the input; temporary captures and qualified names use the caller's arena. This remains a bootstrap reader adapter, not a persistent request artifact.

The native chain fixture now constructs a marked request, validates/selects its entry through the production inspector, and obtains the native address by that selected name rather than a fixed function index. It still supports the fixture's one Code-handle argument and selects phase source/request names in fixture code. There is no general execution/replacement traversal yet: returned requests, argument binding, whole-program iteration, the reference 100,000-call guard, imports and full Code signatures remain outstanding.

`tests/requests.coil` covers raw arguments, outermost/left-to-right discovery, quote shielding, signature and convention prefixes, marker precedence, module qualification, symbol/string entry names, C-string/keyword/integer rejection and missing/unavailable entries. `tools/check-walk.py` tests a different policy and rejects malformed declarations in default, checked and release configurations.

### Owned request execution

`rewrite.requestexecution` combines generated request shapes/walk boundaries with `languages/request_expansion.protocol`. `run!` consumes one original root and optional module tag, borrowed marker/entry registries, and a typed callback accepting a raw request plus an output syntax workspace. It copies the input, walks left-to-right with explicit visit/rebuild tasks, invokes outer requests before their arguments, and re-enters returned syntax using the original module. Rebuilding changes children while retaining container context and identity.

The declared budget permits exactly 100,000 invocations per run. Selection/entry lookup precedes the budget guard. Calls that fail inside the callback count as invocations; a rejected next call never reaches the callback. Reusing a session starts a fresh budget and releases old output/errors. Busy, closed and aliased-input cases fail before resetting storage. Promote successful output before reuse/close if it must survive independently. Generic callback error payloads remain subject to their own ownership rules.

Callbacks may append owned syntax or return an existing root, but must not mutate existing rows/text: the runner retains a projection cache throughout the run. Raw call captures live through that callback only. Inspection scratch storage is reset between calls; output syntax and projected trees remain until reuse/close. The task stack avoids recursive request chaining, while promotion/projection/import still have recursive schema adapters.

`tests/request-execution.coil` covers replacement, returned requests, module tags, metadata, ownership, errors and exact fuel boundaries in three configurations. The native chain fixture uses this runner with an explicit image context and unary Code-handle callback. Batch normalization, top-level splicing, full Code signature checking and the complete frontend remain separate work.

### Declared leaf walks and returned-form batches

A walk may declare `(default keep)` to retain unmatched containers as whole leaves; the default remains `(default children)`. `(prefix-list "do" 1)` descends only into matching lists, unlike `prefix`, which applies to lists and vectors. Defaults may appear anywhere, but at most once. Head rules remain unique and every prefix is checked before generation.

Each policy derives `leaves-NAME(allocator, root)`, an explicit-stack, left-to-right collector. `KeepSyntax` contributes the entire borrowed form; `VisitChildren` contributes only recursively selected children after the prefix, never the parent or excluded prefix. The caller owns the returned pointer array. The input must be a valid acyclic reader graph and outlive every pointer. Repeated occurrences are retained; this is not a graph-deduplication operation. The independent walk fixture traverses 25,000 nested bundles without recursive walker calls; this does not test the recursive owned projection/import adapters.

`walk produced-forms` declares only list-headed `do` bundles transparent. Consequently nested bundles flatten recursively, empty bundles contribute nothing, and ordinary forms (including quotes and vectors) stay intact. `rewrite.produced/normalize!` projects an owned root, applies the generated collector, and imports the selected forms into a distinct owned output. It copies optional module tags, context/identity metadata, and only source documents reached by emitted forms. Returned arrays belong to the caller; rows and strings belong to the output. Errors return no partial array but can leave unreachable rows/documents in output.

`code/import-from!` imports valid acyclic reader syntax using a borrowed source-document registry. It checks spans and immutable document identity while copying metadata. It reports missing/conflicting documents and owns reader diagnostic text. Ordinary `import-form!` uses the target's existing document registry and retains its previous API. Both rely on the generated surface parser and retain recursive import/metadata traversal.

`rewrite.stagedrequests/run!` expands each original `stage/Tagged` root with a fresh request budget, then normalizes its result before advancing to the next root. It returns an ordered owned array whose forms/module tags belong to the supplied output syntax. Request/normalization errors identify the original root index. Keep the execution session alive to inspect a request failure; callback error payloads have their own ownership contract. Inputs and output must be distinct; output cannot be the execution workspace. Failure publishes no array, and external callback effects are not rolled back.

This batch operation is not `do-produced` in full: generated declaration/derive registration and tracked form identity/revision/cache reuse are still missing. In particular, the reference's revision equality includes scope, definition module, origin and flags, unlike datum equality or the current scope/module source-reuse predicate. Neither existing equality predicate is sufficient for revision reuse without extending its metadata policy.

### Field equivalence and form revisions

`(equivalence Name Record field...)` derives a pure C-callable predicate over two borrowed record pointers. It compares only the selected scalar fields, in declaration order; an empty selection is always equivalent. Int, Bool and Text fields are supported. Unknown records/fields, sums, non-scalar fields, duplicate names/fields and malformed declarations are rejected before output. This declaration also works without a structural `equality` root. Structural equality still traverses the schema graph; equivalence supplies its per-node metadata condition.

The syntax schema declares `source-reuse` over scope/module and `revision-reuse` over scope/module/origin/flags. `code/source-equal?` retains its existing behavior through the generated predicate. `code/revision-equal?` uses the second predicate at every compared syntax node. Both share the pair-memoized structural walker; source locations, transport context and node identity are excluded. Datum equality remains separate.

`rewrite.revision` supplies compilation-local identities and version bookkeeping over normalized tagged forms. A singleton with an original keeps its identity; equivalent syntax keeps its revision and cached shape, while changed syntax increments revision and clears the cache. Zero outputs allocate nothing. Multiple outputs, or output without an original, receive fresh identities at revision zero with an empty cache. The comparison uses the original root, so removing a wrapping bundle can change a singleton's revision. Module tags must match the original. The caller owns the returned array; forms and module strings still borrow the normalization output.

A single `Supply` defines one compilation's identity scope. It must cover all original identities supplied for reuse; it is not a cross-compilation or concurrent global ID service. Exhaustion fails before integer wrap, and identities allocated before a later failure stay consumed. The reference's integer increment implementation is not independently matched at the artificial maximum-counter boundary. Revision state validation and comparison failures publish no result array. This counted kernel does not retain syntax or implement the semantic cache itself.

`stagedrequests/run-with!` adds a typed admission callback after each original root is expanded/normalized, before the next root executes. It receives the original root/index, both syntax stores and the temporary normalized array. It can inspect or consume entries in place; it cannot retain that array. Retained syntax must borrow the caller-owned output or be independently promoted. Admission failure reports the original root index, returns no batch array and does not roll back prior callback effects. `run!` selects no-op admission and keeps the existing structural API.

Tracking must use the normalized count before admission consumes registrations, matching the reference's singleton decision. The batch fixture connects admission to revision tracking and checks ordering, failure, retry without recycling IDs, changed/split/unchanged forms and independent output lifetime. Actual derive and declaration registration remains unimplemented; an admission hook alone is not that policy.

### Import refer policies

`languages/names.schema` describes refer data and declares:

```
(refer-policy imports Refer
  (selection all selected text)
  (exclude excluded text)
  (rename renames exported local))
```

The root must be a record: `all` is Bool, the three collections contain records, and selected name/rename fields are Text. Field and record names are checked against the schema; neither layout nor numbered field offsets are hardcoded. Policy names must be unique. The policy compiler derives `refer-NAME(allocator, store, root)` with checked root/child/sequence access and cleanup on failure. The generated builder returns an independently owned `rewrite.refer/Policy`; the input store may then be released. Invalid roots, referenced rows and sequences return structured errors without publishing a policy.

The language's refer semantics are shared by three indexed queries. Forward lookup maps a local name to its exported spelling. Renames are processed in source order: each row first supplies its local name, then suppresses its old exported name; the first decision for a spelling wins. Renames take precedence over both exclusion and selection. Exclusions then suppress names. Selected names refer themselves; `all` supplies an identity fallback for otherwise undecided names.

Reverse lookup maps an exported spelling to its local name using its first rename, then exclusion/selection. It is the reference's `use-local-of` operation, not a mathematical inverse under overlapping rename rows. `drops?` separately records every excluded or renamed source spelling, even for self-renames. Absence from an explicit selection is not a deliberate drop. These distinctions matter for ambient names and trait-method visibility.

`refer/referred`, `refer/local-name` and `refer/drops?` use owned hash indexes. Explicit answers borrow the policy's string pool; an all-names identity fallback borrows the query string. `refer/release!` frees the indexes and owned text. Build a new snapshot when import data changes. The low-level builder operations assume rename/exclude/select order; consumers use the schema-derived builder. This replaces scans per query with hash lookup, but is not a measured whole-compiler performance claim.

`tools/capture-refer-reference.py` extracts exact refer helper/type definitions from the installed reference compiler's reported source revision and compiles them in isolation. Its evidence covers 43 policies and 387 queries in three configurations. `tools/check-refer.py` replays those observations through two different generated record layouts in all three configurations. Some collision cases exercise helper data that may not be accepted by the source import parser; no source-import compatibility follows. `tests/refer.coil` checks 2,000 renames, independent ownership, invalid references/sequences, late failure and retry with explicit allocator leak checking.

This is the edge-level refer operation shared by use imports, reexports and ambient core, not a complete namespace resolver. Alias routing, declaration aliases, export visibility, recursive reexports, tier priority, ambiguity, core-provider ownership and hygiene-based macro-head lookup remain to be implemented and integrated with admission.
